# Highlight Translate MVP V1 规格

- 状态：Ready for agent
- 适用范围：仅供本人在本机 Chrome 中使用的 MVP
- 目标语言：简体中文
- 模型提供商：DeepSeek
- 固定模型：`deepseek-v4-flash`
- 规格日期：2026-08-09

本文档是 MVP V1 的权威规格。若早期方案、调研记录与本文档冲突，以本文档为准。

## Problem Statement

用户在 Chrome 中阅读外语网页时，需要频繁复制文本、切换翻译工具、粘贴并等待结果，阅读过程被打断。用户希望在当前网页内通过鼠标或触控板选中文字，以最少操作调用自己的 DeepSeek API Key，将所选内容翻译成简体中文。

现有通用翻译产品对混合语言选区、同语言文本、隐私数据范围和大模型流式响应的处理不完全符合用户预期。MVP 需要建立一套明确且可测试的边界：完整选区只判断一种主要源语言；中文选区不调用模型；非中文或未知语言选区才调用 DeepSeek；发送给第三方的页面数据严格限定为用户选中的完整文本。

## Solution

构建一个 Chrome Manifest V3 扩展。用户在普通网页正文中用鼠标或触控板完成有效选区后，选区末端附近出现圆形“译”按钮。点击按钮后，扩展在本地检测完整选区的主要语言：识别为中文时直接在翻译卡片中显示原文；识别为非中文或仍未知时，由 Extension Service Worker 使用用户保存在本机的 API Key 调用 DeepSeek，并把流式翻译结果展示在当前页面。

扩展固定翻译到简体中文，MVP 固定使用 DeepSeek 的 `deepseek-v4-flash`，同时在内部保留模型提供商适配边界。翻译卡片支持关闭、重试和复制；设置页只负责 API Key 的保存与独立连接测试。扩展不保存翻译历史或缓存，不向模型发送页面标题、URL、DOM、上下文或其他页面信息。

## User Stories

1. 作为仅在本机使用扩展的用户，我希望通过加载已解压扩展程序完成安装，以便无需应用商店发布流程即可使用。
2. 作为首次安装扩展的用户，我希望安装完成后只自动打开一次设置页，以便立即配置 API Key。
3. 作为日常使用扩展的用户，我希望点击浏览器工具栏图标直接进入设置页，以便随时维护 API Key。
4. 作为日常使用扩展的用户，我不希望工具栏图标打开额外弹窗，以便设置入口保持单一。
5. 作为更新或开发重载扩展的用户，我不希望设置页被反复自动打开，以免打断当前工作。
6. 作为设置扩展的用户，我希望保存自己的 DeepSeek API Key，以便后续翻译请求可以直接使用。
7. 作为关注隐私的用户，我希望 API Key 只长期保存在本机扩展存储中，直到我清除数据或卸载扩展。
8. 作为关注密钥安全的用户，我希望设置页默认遮盖 API Key，以避免旁人直接看到完整密钥。
9. 作为设置扩展的用户，我希望保存配置与测试连接彼此独立，以便测试失败时仍能决定是否保存 Key。
10. 作为设置扩展的用户，我希望只有主动点击“测试连接”才发送最小测试请求，以免保存时产生非预期调用。
11. 作为阅读网页的用户，我希望在普通 HTTP 或 HTTPS 顶层页面中使用划词翻译，包括本地开发服务器。
12. 作为使用扩展的用户，我希望扩展明确不在 Chrome 内部页面、Chrome Web Store、`file://` 页面、内置 PDF 和 iframe 中运行，以避免能力不一致。
13. 作为阅读正文的用户，我希望用鼠标或触控板完成选区后出现翻译入口，以便自然衔接阅读动作。
14. 作为使用键盘选择文本的用户，我接受 MVP 不为键盘选区显示翻译入口，以便第一版保持交互范围清晰。
15. 作为在表单中编辑内容的用户，我不希望扩展处理 `input`、`textarea` 或 `contenteditable` 内的选区，以避免干扰输入行为。
16. 作为选中文字的用户，我希望在选区末端右下方约 8 像素处看到圆形“译”按钮，以便入口靠近当前操作位置。
17. 作为在视口边缘选中文字的用户，我希望按钮自动翻转或限制在可视区域内，以便入口始终可以点击。
18. 作为只选中空白、纯数字、纯标点、纯 Emoji、纯 URL 或纯邮箱的用户，我不希望看到翻译按钮，因为这些内容不是本功能要处理的自然语言。
19. 作为选中正常句子的用户，我希望句子中的 URL 或邮箱作为完整选区的一部分保留，以免翻译破坏原始信息。
20. 作为选中代码或变量名的用户，我希望 MVP 不做额外的代码识别和过滤，以便规则保持可预测。
21. 作为选中极短自然语言文本的用户，我希望只要存在至少一个有效字符就可以看到翻译按钮，以便单词也能翻译。
22. 作为选中超过 5,000 字符文本的用户，我希望仍能看到翻译按钮，并在点击后得到“内容过长”的明确提示，而不是调用模型。
23. 作为选中非中文文本的用户，我希望完整选区被翻译为简体中文，以便快速理解内容。
24. 作为选中中文文本的用户，我希望点击“译”后原样看到中文，并且不调用 DeepSeek，以避免无意义请求。
25. 作为选中中外文混合内容的用户，我希望完整选区只识别一种主要源语言，以便行为与主流整段翻译方式一致。
26. 作为选中以中文为主要语言的混合内容的用户，我希望英文部分也不被单独翻译，以便严格遵守整块单语言判定规则。
27. 作为选中语言无法可靠判断的文本的用户，我希望完整选区交给 DeepSeek 翻译，以便仍有机会得到结果。
28. 作为查看结果的用户，我希望卡片显示语言方向，以便知道扩展采用了什么语言路由。
29. 作为查看可靠源语言结果的用户，我希望看到类似“英语 → 简体中文”的方向标签，以便理解检测结果。
30. 作为查看未知源语言结果的用户，我希望看到“自动检测 → 简体中文”，以免扩展伪装成已可靠识别语言。
31. 作为查看中文选区结果的用户，我希望卡片显示“中文”和原始中文，以便明确知道没有执行翻译。
32. 作为阅读页面的用户，我希望翻译卡片不重复显示非中文原文，因为原文仍保留在页面选区中。
33. 作为发起翻译的用户，我希望点击按钮后立即看到卡片和流式增长的译文，以便无需等待完整响应。
34. 作为查看长译文的用户，我希望卡片保留段落、换行、缩进、编号和分点，以便译文结构与原文一致。
35. 作为选区包含代码、URL 或占位符的用户，我希望这些内容作为纯文本被保留，以免格式或含义被破坏。
36. 作为查看模型结果的用户，我不希望看到模型思考过程、额外解释、音标、例句或扩展内容，以便卡片只呈现翻译。
37. 作为查看流式译文的用户，我希望卡片在我停留于底部时自动跟随最新内容，以便持续阅读。
38. 作为主动向上滚动译文的用户，我希望自动滚动暂停，以免阅读位置被强制拉走。
39. 作为重新滚动到底部的用户，我希望自动跟随恢复，以便继续查看新内容。
40. 作为等待翻译的用户，我希望流式响应期间复制按钮不可用，以免复制到仍在变化的内容。
41. 作为得到完整结果的用户，我希望点击复制按钮只复制结果文本，并看到短暂的“已复制”反馈。
42. 作为遇到中途失败的用户，我希望保留已经收到的部分译文、看到“翻译未完成”标记，并可以复制部分内容。
43. 作为遇到中途失败的用户，我希望点击重试后重新发起完整请求，并在首个新片段到达时替换旧的部分结果。
44. 作为遇到网络或服务错误的用户，我希望看到可理解的错误信息和适当的重试入口，而不是内部堆栈或原始敏感响应。
45. 作为尚未配置 API Key 的用户，我希望选中文字后仍可打开卡片，并从“前往设置”进入设置页，而不是被自动跳转。
46. 作为连续选择不同文本的用户，我希望新选区关闭旧卡片并取消旧请求，以免过期结果覆盖当前内容。
47. 作为不再需要结果的用户，我希望通过关闭按钮、`Esc` 或点击页面空白处关闭卡片并取消请求。
48. 作为滚动或调整窗口大小的用户，我希望卡片保持打开且不取消翻译，以便操作页面时不丢失结果。
49. 作为滚动页面的用户，我希望卡片继续锚定原选区并随页面移动，离开视口后自然不可见，滚回时再次出现。
50. 作为使用不同系统主题的用户，我希望卡片跟随系统浅色或深色偏好，而不是被宿主网页主题左右。
51. 作为查看较长结果的用户，我希望卡片宽度适应在约 360 至 480 像素之间、高度不超过视口的 60%，超出内容在卡片内部滚动。
52. 作为关注隐私的用户，我希望翻译请求只携带完整选区文本，不携带页面标题、URL、DOM、选区前后文或富文本样式。
53. 作为关注隐私的用户，我希望 API Key 和选中文本不会进入页面 DOM、Content Script 日志、构建产物或版本控制。
54. 作为日常使用扩展的用户，我不希望翻译结果被缓存或记入历史，以便关闭卡片后不留下内容记录。
55. 作为个人用户，我不需要扩展内的站点黑名单或暂停开关，因为可以使用 Chrome 自带的站点访问控制。
56. 作为简体中文用户，我希望 MVP 的全部界面文案固定为简体中文，以便界面一致。
57. 作为未来可能扩展功能的维护者，我希望界面文案集中管理，以便后续增加国际化时无需重写业务逻辑。
58. 作为未来可能切换模型服务的维护者，我希望 DeepSeek 调用位于提供商适配边界之后，以便扩展新提供商时不改动选择和卡片流程。
59. 作为维护者，我希望扩展可稳定构建出可加载的目录，以便每次修改后能在 Chrome 中重复验证。

## Implementation Decisions

### 产品范围与运行环境

- MVP 仅供用户本人在本机 Chrome 中使用，不包含公开分发、Chrome Web Store 上架、账号系统、服务端或多人能力。
- 采用 Chrome Manifest V3。
- 支持普通顶层 HTTP/HTTPS 页面，包括本地开发服务器。
- 排除 Chrome 内部页面、Chrome Web Store、`file://` 页面、Chrome 内置 PDF 和所有 iframe。
- 不提供扩展内站点黑名单或暂停开关；站点权限由 Chrome 自身控制。

### 技术架构

- 使用 TypeScript、Vite、原生 HTML/CSS/DOM API 和 Chrome Extension APIs。
- MVP 不引入 React、Vue 或完整扩展框架。
- Content Script 负责选区监听、选区坐标、触发按钮、翻译卡片和页面内交互。
- Extension Service Worker 负责读取可信配置、校验消息、执行语言路由、调用模型、解析流、超时与取消、错误归一化。
- Options Page 负责 API Key 的展示、保存和独立连接测试。
- 共享领域模块承载消息契约、配置契约、语言检测结果、请求状态、错误类型、固定提示词和集中式简体中文文案。
- 页面内 UI 放入 Shadow DOM，避免宿主页面与扩展之间的样式污染。
- 模型输出只按不可信纯文本渲染，不将其作为 HTML 执行。

### 选区与触发规则

- 仅响应鼠标或触控板完成的普通网页正文选区；不响应键盘选区、右键菜单和快捷键。
- 不处理 `input`、`textarea` 或 `contenteditable` 中的选区。
- 选区的原始完整文本是后续展示或请求的数据源。可以用仅供校验的派生文本判断有效性，但不得因此修改实际发送内容。
- 有效选区至少包含一个有效自然语言字符，且不超过 5,000 字符。
- 纯数字、纯标点、纯空白、纯 Emoji、纯 URL、纯邮箱不显示翻译按钮。
- URL 或邮箱夹在正常自然语言内容中时，作为完整选区的一部分保留。
- MVP 不额外识别或过滤代码片段、变量名。
- 超过 5,000 字符时保留触发按钮；点击后在卡片中提示内容过长，不检测语言、不调用模型。
- 触发按钮为圆形“译”，锚定选区末端右下方约 8 像素；遇到视口边缘时自动翻转或限制在可见范围内。

### 语言检测与翻译路由

- 一次选区始终作为一个不可拆分的语言单元，只识别一种主要源语言，不按中文、英文或其他语言片段拆分。
- 首选 `chrome.i18n.detectLanguage` 在本地检测完整选区。
- 对极短文本或不可靠结果使用 Unicode 规则兜底，包括对中文、日文假名和韩文字符的确定性识别。
- 所有中文变体统一进入“中文”产品类别。
- 识别为中文时，不调用 DeepSeek，卡片原样显示完整选区；中文为主的混合选区同样不翻译其中的外语部分。
- 识别为非中文时，将完整选区发送给 DeepSeek，并翻译为简体中文。
- 本地检测后仍为未知时，将完整选区发送给 DeepSeek；方向标签显示“自动检测 → 简体中文”。
- 目标语言在 MVP 中固定为简体中文，不提供目标语言设置或切换入口。
- 可靠识别源语言时显示“源语言 → 简体中文”；中文原样结果显示“中文”。

### DeepSeek 提供商边界

- MVP 的模型提供商固定为 DeepSeek，API 基础地址固定为 DeepSeek 官方 HTTPS 地址。
- 模型固定为 `deepseek-v4-flash`，不向用户提供模型名称或 API 基础地址编辑入口。
- 内部通过提供商适配接口隔离 DeepSeek 特有的请求、流解析与错误映射，但 MVP 不实现其他提供商。
- 使用 Chat Completions 流式响应，以长连接消息通道把增量事件从 Service Worker 传给 Content Script。
- 请求关闭模型思考模式；不得展示、转发或保存 `reasoning_content`。
- 模型输出采用纯翻译文本流，不要求模型输出 JSON。
- 固定提示词要求：只翻译、保持原有文本结构、保留代码/URL/占位符、不添加解释，并把选区内容当作待翻译数据而非可执行指令。
- 从当前网页提取并发送给第三方的内容只能是用户选中的完整文本。不得发送页面标题、URL、DOM、HTML/CSS、选区前后文或其他页面元数据。

### API Key 与隐私安全

- API Key 由用户在设置页输入，去除首尾空白后保存到 `chrome.storage.local`，直到用户清除扩展数据或卸载扩展。
- 本地存储访问级别限制为可信扩展上下文；Content Script 不得读取、接收或展示 API Key。
- 只有 Extension Service Worker 负责添加鉴权信息，并且只允许请求固定的 DeepSeek HTTPS 主机。
- API Key 不得写入源码、构建产物、日志、页面 DOM 或版本控制。
- 不记录用户选中的文本，也不记录可能包含该文本的模型请求或响应正文。
- Service Worker 必须校验消息来源、消息类型、请求标识、文本类型和长度，不允许 Content Script 指定任意请求地址、模型或鉴权信息。
- `chrome.storage.local` 不是系统级密钥保险箱；该取舍只适用于本人本机使用的 BYOK MVP。

### 翻译卡片与交互状态

- 点击“译”后在相同锚点展开翻译卡片。
- 对非中文翻译，卡片只显示语言方向、结果区、状态操作和关闭按钮，不重复显示原文。
- 对中文选区，结果区原样显示中文，并视为本地立即完成的结果。
- 卡片跟随系统 `prefers-color-scheme`，不根据宿主网页主题切换。
- 卡片宽度在约 360 至 480 像素之间自适应，最大高度为视口的 60%；超出内容在卡片内部滚动，并保留空白、换行和缩进。
- 流式输出时，仅当用户位于内容底部才自动滚动；用户向上滚动后暂停，返回底部后恢复。
- 翻译完成前复制按钮禁用；完成后可复制结果并短暂显示“已复制”。
- 流中断且已有部分内容时，保留部分内容、标记“翻译未完成”，并允许复制部分结果。
- 页面滚动和窗口缩放不关闭卡片、不取消请求。卡片持续锚定原选区并随文档移动；窗口缩放时重新计算位置。
- 关闭按钮、`Esc`、点击页面空白处或产生新选区会关闭旧卡片；如有活动请求，同时取消。

### 请求生命周期、超时与错误

- 每次翻译使用唯一请求标识；所有增量、完成、错误和取消事件都携带该标识。
- Content Script 只接受当前活动请求的事件，任何旧请求结果都不得覆盖新结果。
- 新选区或关闭卡片会通过取消消息和 `AbortController` 尽力终止旧网络请求。
- 首个有效内容等待上限为 20 秒；流中相邻有效内容的空闲上限为 20 秒；单次请求总时长上限为 120 秒。
- 超时、网络错误、限流、鉴权失败、余额或额度问题、服务端错误、空响应和无效流都映射为不泄露内部信息的简体中文错误。
- MVP 不自动重试。
- 用户点击重试会从头发起完整请求；旧部分结果保持可见，直到新请求的第一个内容片段到达后被替换。
- 如果没有 API Key，卡片显示缺少配置及“前往设置”操作，不自动跳转设置页。

### 设置页与扩展生命周期

- 设置页只提供遮盖的 DeepSeek API Key 输入、保存、清除或替换能力，以及独立的“测试连接”按钮。
- 不提供模型、API 基础地址、目标语言、源语言偏好或释义选项。
- 保存 API Key 不自动执行连接测试；连接测试成功或失败不影响保存行为。
- 连接测试使用最小请求，并以不暴露密钥或原始内部响应的方式显示结果。
- 仅首次安装自动打开一次设置页；更新和开发重载不重复打开。
- 工具栏图标直接打开设置页，不提供 toolbar popup。

### 数据保留与界面语言

- 不实现翻译缓存、翻译历史、收藏或单词本。
- 关闭卡片后丢弃本次翻译结果；当前活动结果只存在于本次页面会话的 UI 状态中。
- MVP 全部界面文案固定为简体中文。
- 文案集中管理，为未来国际化保留边界，但 MVP 不提供语言切换。

## Testing Decisions

### 测试原则

- 自动化测试只断言用户可观察行为和扩展公开契约，不断言私有函数、内部调用顺序、DOM 实现细节或具体目录结构。
- 优先使用一个最高层主测试接缝，减少同一规则在多层重复测试和实现重构造成的脆弱性。
- 时间、Chrome API、存储和网络必须可替换，以便测试可重复、无需真实 API Key、不会产生真实 DeepSeek 调用。
- 所有失败场景都必须证明不会泄露 API Key、选区文本、堆栈或未经归一化的服务端响应。

### 主自动化测试接缝

- 唯一主接缝是 Content Script 与 Extension Service Worker 之间的长连接消息协议。
- 测试从“提交完整选区翻译请求”开始，观察语言方向、流式内容、完成、错误、取消和重试等公开事件。
- 在接缝后替换语言检测、可信配置存储、DeepSeek 流、剪贴板结果和可控计时器，不直接测试其私有实现。
- 通过该接缝覆盖：消息校验、5,000 字符边界、中文不调用模型、非中文调用模型、未知语言调用模型、混合语言主语言路由、SSE 分片解析、格式保留、错误映射、三类超时、无自动重试、部分结果保留、重试替换、取消和过期请求隔离。
- 通过捕获提供商适配器收到的请求，验证只包含固定指令和完整选区，不包含页面标题、URL、DOM、前后文、可编辑模型参数或来自 Content Script 的密钥。

### 页面交互与手动验收

- 由于当前项目没有既有浏览器测试基础设施，MVP 先以可重复的 Chrome 手动验收验证真实 DOM、选区几何和扩展生命周期；不为第一版新建重型端到端测试框架。
- 手动覆盖：鼠标/触控板选区、键盘选区不触发、正文与可编辑区域边界、纯 URL/邮箱等无按钮规则、按钮靠近选区及视口翻转、Shadow DOM 样式隔离、浅深色主题。
- 手动覆盖：英文、中文、中英混合、未知短文本、超过 5,000 字符、无 Key、错误 Key、流式中断、重试、连续新选区、关闭取消、复制反馈。
- 手动覆盖：滚动和窗口缩放不关闭、原选区锚定、离开并返回视口、长内容内部滚动和自动跟随暂停/恢复。
- 手动覆盖：首次安装打开设置一次、更新或重载不重复打开、工具栏图标直接进入设置、保存与测试连接互不影响。

### 构建与安全验证

- 提供稳定的生产构建命令，输出可由 Chrome“加载已解压的扩展程序”直接加载的目录。
- 构建验证至少检查 Manifest V3 配置、必要入口、固定 DeepSeek 主机权限和未申请无关高风险权限。
- 对源码和构建产物执行敏感信息扫描，确认不存在真实 API Key、选区样本日志或意外打包的本地配置。
- 在真实 Chrome 中完成至少一轮从安装、配置、选区、流式翻译、复制到关闭的端到端验收。

### 既有测试先例

- 当前仓库只有方案和调研文档，没有可复用的自动化测试或浏览器测试先例。
- 实现阶段应以本规格确定的长连接消息协议作为首个稳定公开测试接缝，避免先为内部模块建立彼此重叠的低层测试体系。

## Out of Scope

- 面向他人或团队使用、公开分发、Chrome Web Store 上架与合规流程。
- 用户账号、登录、云端同步、多设备同步、后台代理、密钥托管、限流、配额统计和计费。
- DeepSeek 之外的实际提供商实现；自定义 API 地址、自定义模型和模型切换。
- 简体中文之外的目标语言和界面语言；自动反向翻译中文。
- 键盘选区触发、键盘快捷键、右键菜单和 toolbar popup。
- `input`、`textarea`、`contenteditable`、iframe、`file://`、内置 PDF、图片 OCR 和网页全文翻译。
- 按语言片段拆分混合选区，或只翻译混合文本中的外语部分。
- 专门的代码、变量名、术语、URL 或邮箱翻译模式。
- 富文本、HTML、CSS、页面样式或 DOM 结构的提取、发送与还原。
- 音标、词典释义、例句、解释、改写、总结、推理过程和多候选译文。
- 翻译缓存、翻译历史、收藏、单词本和关闭卡片后的结果恢复。
- 自动重试、请求排队、并行展示多个翻译卡片和后台持续翻译。
- 扩展内站点黑名单、站点暂停开关和自定义主题。
- Chrome `LanguageDetector` 本地 AI 模型和第三方语言检测库；除非后续实测证明当前方案不满足准确率要求。
- 为 MVP 新建重型浏览器端到端自动化框架。

## Further Notes

- “完整选区只判断一种主要源语言”是明确的产品规则，不是暂时的算法限制。实现不得擅自拆分混合文本。
- “中文原样显示”发生在本地语言检测之后；它仍需经过用户点击“译”的显式动作，但不产生 DeepSeek 调用。
- “只发送用户选中的完整文本”限定的是从当前页面提取的用户数据。请求可以包含扩展内固定的系统翻译指令，但不得附加任何其他页面信息。
- 早期方案中的“中文翻译为英文”“非流式响应”“用户可配置模型和目标语言”“卡片重复显示原文”等内容均已失效。
- 既有竞品调研支持采用完整选区、单一主要源语言、单一目标语言的主流模型；既有检测方案调研支持采用 `chrome.i18n.detectLanguage` 加 Unicode 兜底。
- 本地规格已经达到可拆分开发任务的状态。项目尚未配置 Git 仓库和 issue tracker，因此本次无法发布 issue 或应用 `ready-for-agent` 标签；文档头部的 “Ready for agent” 表示同等的本地状态。
