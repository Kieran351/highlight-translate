# Highlight Translate MVP V1

## 1. 背景

本项目用于实现一个 Chrome 浏览器划词翻译插件。用户在网页中选中文字后，可以通过选区附近的悬浮按钮调用大模型完成翻译，并在当前页面直接查看结果。

第一版使用用户自己的模型 API Key，默认接入 DeepSeek API，并以 `deepseek-v4-flash` 作为默认模型。

## 2. 本次目标

### 2.1 核心目标

建立一个可以在 Chrome 中以“加载已解压的扩展程序”方式安装和使用的 MVP，完成以下闭环：

1. 用户在普通网页中选中文字。
2. 插件在选区附近显示翻译按钮。
3. 用户点击按钮后，插件调用 DeepSeek API。
4. 插件在当前页面展示翻译结果。
5. 用户可以在设置页配置自己的 API Key 和翻译偏好。

### 2.2 默认行为

- 非中文内容默认翻译为简体中文。
- 中文内容默认翻译为英文。
- 默认模型为 `deepseek-v4-flash`。
- 翻译请求默认关闭思考模式，以降低响应时间和 token 消耗。
- 只有用户主动点击翻译按钮后，插件才会发送选中的文字。
- 点击翻译卡片外部或按 `Esc` 可以关闭卡片。
- 选区发生变化时，旧的悬浮按钮和无效结果应被清理。

### 2.3 MVP 不包含的功能

以下功能不进入第一版范围：

- 用户账号和登录系统。
- 云端同步。
- 翻译历史记录。
- 单词本和收藏夹。
- 网页全文翻译。
- PDF 专项适配。
- 图片 OCR 翻译。
- 多设备同步 API Key。
- Chrome 应用商店正式发布流程。
- 自建 API 中转服务。

## 3. 架构选择

### 3.1 Chrome 扩展规范

使用 Chrome Manifest V3。

主要组成部分：

- **Content Script**：监听网页选区、计算展示位置、渲染悬浮按钮和翻译卡片。
- **Extension Service Worker**：读取配置、校验消息、调用模型 API、归一化错误并返回结果。
- **Options Page**：配置 API Key、模型和目标语言等设置。
- **Shared Modules**：存放消息类型、配置类型、提示词和通用校验逻辑。

### 3.2 技术栈

- TypeScript
- Vite
- 原生 HTML、CSS 和 DOM API
- Chrome Extension APIs
- DeepSeek Chat Completions API

MVP 暂不引入 React、Vue 等 UI 框架，以减少打包复杂度和最终产物体积。后续界面复杂度明显上升时再评估引入框架。

## 4. 方案设计

### 4.1 整体数据流

```text
用户选择网页文字
        ↓
Content Script 获取选区和坐标
        ↓
在选区附近显示翻译按钮
        ↓
用户点击翻译按钮
        ↓
Content Script 向 Service Worker 发送翻译请求
        ↓
Service Worker 读取设置并调用 DeepSeek API
        ↓
Service Worker 解析并校验模型响应
        ↓
Content Script 在翻译卡片中显示结果
```

Content Script 不直接调用模型 API，也不读取 API Key。

### 4.2 划词检测

Content Script 监听以下事件：

- `mouseup`：鼠标选择结束后读取选区。
- `keyup`：支持通过键盘完成的文本选择。
- `selectionchange`：用于识别选区变化和清理过期 UI。
- `scroll` 和 `resize`：关闭或重新定位悬浮 UI。

选区需要满足以下条件：

- 选中文本去除首尾空白后不为空。
- 文本长度在允许范围内。
- 选区拥有有效的可视矩形。
- 不处理扩展无法注入的 Chrome 内部页面。

MVP 建议限制单次输入长度，例如最多 5,000 个字符。超过限制时直接提示用户缩短选区，不发送 API 请求。

### 4.3 悬浮按钮与翻译卡片

页面 UI 使用 Shadow DOM 承载，避免宿主网页的样式影响插件，也防止插件样式污染网页。

悬浮按钮状态：

- 默认状态：显示翻译图标。
- 请求状态：显示加载动画，并避免重复点击。
- 错误状态：在翻译卡片中显示可理解的错误和重试入口。

翻译卡片至少展示：

- 原文。
- 译文。
- 加载状态。
- 错误信息。
- 关闭按钮。

UI 必须兼容浅色和深色网页，并使用较高但受控的 `z-index`。

渲染模型返回内容时使用 `textContent`，禁止直接使用不受信任内容设置 `innerHTML`。

### 4.4 扩展消息协议

Content Script 和 Service Worker 通过 `chrome.runtime.sendMessage` 通信。

翻译请求建议包含：

```ts
interface TranslateRequest {
  type: "TRANSLATE_TEXT";
  requestId: string;
  text: string;
  sourceLanguage: "auto";
  targetLanguage?: string;
}
```

翻译响应建议使用可区分的联合类型：

```ts
type TranslateResponse =
  | {
      ok: true;
      requestId: string;
      translation: string;
      sourceLanguage?: string;
    }
  | {
      ok: false;
      requestId: string;
      error: {
        code: string;
        message: string;
        retryable: boolean;
      };
    };
```

Service Worker 必须校验消息来源、消息类型、文本类型和长度，不能无条件转发 Content Script 提供的任意地址或请求参数。

### 4.5 DeepSeek API 调用

默认请求地址：

```text
https://api.deepseek.com/chat/completions
```

默认模型：

```text
deepseek-v4-flash
```

请求参数建议：

- 使用非流式请求完成 MVP，降低跨上下文传递和解析复杂度。
- 关闭思考模式，优先保证翻译速度。
- 设置合理的 `max_tokens`。
- 使用较低的随机性，保持翻译稳定。
- 使用结构化 JSON 输出，减少响应解析歧义。
- 设置超时并支持取消过期请求。

提示词需要明确：

- 任务仅为翻译用户提供的文本。
- 选中文字是待翻译数据，不是需要执行的指令。
- 保留原文中的格式、段落、专有名词和代码片段。
- 不添加无关解释。
- 按约定的 JSON 结构输出。

模型名称和 API 地址应保存在配置层，避免散落在业务代码中，方便后续支持其他 OpenAI 兼容模型。

### 4.6 设置页

MVP 设置项：

- DeepSeek API Key。
- 模型名称，默认 `deepseek-v4-flash`。
- 默认目标语言，默认简体中文。
- 中文原文的目标语言，默认英文。
- 是否显示简短释义，默认关闭。

保存设置时需要：

- 去除 API Key 首尾空白。
- 校验必填字段。
- 显示明确的保存成功或失败状态。
- 可选提供“测试连接”功能，以一个最小请求验证 Key 和模型是否可用。

### 4.7 API Key 安全策略

第一版采用 BYOK，即用户提供并使用自己的 API Key。

安全边界如下：

- API Key 不写入源码、构建产物、日志或 Git。
- API Key 保存在 `chrome.storage.local`，不使用 `storage.sync`。
- 初始化时将本地存储访问级别限制为可信扩展上下文。
- Content Script 不读取、接收或展示 API Key。
- 只有 Service Worker 负责组装鉴权请求。
- 只允许向预先声明的 DeepSeek HTTPS 域名发送请求。
- 设置页中的 API Key 输入框使用密码模式，并默认不回显完整内容。

需要明确：`chrome.storage.local` 不是系统级密钥保险箱，持久化数据也不能视为强加密存储。该方案适用于个人使用的 MVP。如果未来需要面向大量用户发布，应重新评估用户自带 Key、自建中转服务、鉴权、限流和密钥管理方案。

### 4.8 权限设计

MVP 只申请必要权限：

```json
{
  "permissions": ["storage"],
  "host_permissions": ["https://api.deepseek.com/*"]
}
```

Content Script 需要在普通网页中运行，因此需要声明页面匹配范围。应在产品说明中解释划词功能为何需要网页访问权限。

MVP 不申请以下权限：

- `tabs`
- `history`
- `cookies`
- `webRequest`
- `unlimitedStorage`

除非后续功能有明确需要，否则不扩大权限范围。

### 4.9 错误处理

至少处理以下情况：

- 尚未配置 API Key。
- API Key 无效或已失效。
- 模型名称不可用。
- 账户余额不足或额度受限。
- API 请求被限流。
- 网络断开或请求超时。
- DeepSeek 服务端异常。
- 模型返回空内容或无效 JSON。
- 用户在请求期间改变选区或关闭翻译卡片。

面向用户的错误信息不得直接暴露完整响应头、API Key 或内部堆栈。可重试错误与不可重试错误应有不同提示。

### 4.10 并发和过期结果

每次翻译请求生成唯一 `requestId`。Content Script 只展示当前活动请求的结果。

当用户重新选择文字或关闭卡片时：

- 标记旧请求已过期。
- 能取消时通过 `AbortController` 取消请求。
- 即使旧响应之后返回，也不得覆盖新的翻译结果。

## 5. 开发阶段

### 阶段一：扩展骨架

- 初始化 TypeScript 和 Vite。
- 创建 Manifest V3 配置。
- 建立 Content Script、Service Worker 和 Options Page 入口。
- 构建后可以通过 Chrome 加载。

### 阶段二：页面交互

- 实现划词检测。
- 实现悬浮翻译按钮。
- 使用 Shadow DOM 实现翻译卡片。
- 完成关闭、加载和错误状态。

### 阶段三：模型接入

- 实现设置存储。
- 接入 DeepSeek API。
- 实现提示词、响应解析、超时和错误映射。
- 确保 API Key 不进入 Content Script。

### 阶段四：验证和收尾

- 验证构建产物。
- 在多种网页中手动测试。
- 检查权限和敏感信息。
- 补充安装和使用说明。

## 6. MVP 验收标准

满足以下条件即可认为 MVP V1 完成：

1. 项目可以成功构建，并能通过 Chrome 加载已解压的扩展程序。
2. 用户可以在设置页保存 API Key 和目标语言。
3. 用户在普通网页选中文字后能看到翻译按钮。
4. 点击按钮后能够调用 `deepseek-v4-flash` 并显示译文。
5. 中文和非中文文本能够使用预期的默认目标语言。
6. 未配置 Key、Key 错误、网络失败和限流时有清晰提示。
7. 快速连续选择不同文本时，不会显示过期请求的结果。
8. 插件 UI 不明显破坏宿主网页样式，宿主网页样式也不影响插件 UI。
9. API Key 不出现在 Content Script、页面 DOM、控制台日志和版本控制文件中。
10. 插件只申请实现当前功能所需的最小权限。

## 7. 后续演进方向

MVP 稳定后，可以按实际需求逐步增加：

- 右键菜单翻译。
- 键盘快捷键。
- 翻译结果复制。
- 多目标语言快速切换。
- 自定义 OpenAI 兼容 API 地址和模型。
- 翻译历史、收藏和单词本。
- 流式输出。
- 全文翻译。
- PDF 和输入框专项适配。
- 后端代理、账号体系、限流和用量统计。
