# Highlight Translate

[English](README.md) | [简体中文](README.zh-CN.md)

不用离开当前网页，就能把选中的外语文本翻译为简体中文。Highlight Translate 是一个供个人使用的 Chrome 划词翻译扩展：中文选区在本地处理，其他选区使用你选定的官方供应商、模型和自己的 API Key 获取流式译文。

- 选中文字后，点击选区旁的小按钮即可翻译。
- 在紧凑的页面内卡片中阅读流式结果，并保留段落、换行和列表结构。
- 翻译完成、部分完成、本地完成或报错后，可拖动标题栏把卡片移到不遮挡正文的位置。
- 请求停止后，可拖动右下角手柄调整卡片宽高；长译文只在结果区内滚动。
- API Key 不进入网页脚本：它只保存在受信任的 Chrome 扩展存储中，并由 Service Worker 使用。
- 只发送你选中的完整文本，不发送页面 URL、标题、DOM、前后文或富文本标记。
- 避免无意义的模型请求：中文选区会在本地检测并原样展示。
- 每家供应商保留一套配置，模型从对应供应商的 API 列表中选择。

Highlight Translate 是一个需要自备 API Key、从 GitHub 本地安装的个人项目。它未发布到 Chrome 应用商店，不包含 API 额度，也不运行项目方维护的后端服务。

## 安装

你需要当前版本的桌面端 Google Chrome、带 npm 的 Node.js，以及下列任一供应商的官方 API Key，用于翻译非中文文本。

```bash
git clone https://github.com/Kieran351/highlight-translate.git
cd highlight-translate
npm install
npm run build
```

然后在 Chrome 中加载构建产物：

1. 打开 `chrome://extensions`。
2. 启用右上角的**开发者模式**。
3. 点击**加载已解压的扩展程序**。
4. 选择项目中的 `dist/` 目录，而不是仓库根目录。
5. 请保持项目目录位置不变。移动或删除目录后，需要从新位置重新加载扩展。

拉取更新或修改源码后，重新运行 `npm run build`，在扩展卡片上点击**重新加载**，再刷新需要使用扩展的网页。

## 选择供应商与模型

1. 从供应商的官方平台取得 API Key；MiniMax 和 Kimi 使用国内站。
2. 打开 Highlight Translate 设置页。首次安装时会自动打开；之后可点击浏览器工具栏中的扩展图标，或在 `chrome://extensions` 中进入**详情 → 扩展程序选项**。
3. 选择供应商，把 Key 粘贴到遮盖显示的 **API Key** 输入框，扩展会自动获取模型列表。
4. 从下拉框选择模型，点击**保存并启用**。测试是可选操作，不是保存的前置条件。
5. 需要更新列表时点击**刷新模型列表**；刷新失败会保留上次成功列表和选择。

不要把 API Key 粘贴到 AI 对话、源码、截图、Issue 或公开消息中。请只在扩展设置页中亲自输入。

| 供应商 | 官方平台 | API 主机 |
| --- | --- | --- |
| DeepSeek | [DeepSeek](https://platform.deepseek.com/) | `api.deepseek.com` |
| MiniMax | [国内站](https://platform.minimax.cn/) | `api.minimax.cn` |
| Kimi／月之暗面 | [国内站](https://platform.kimi.com/) | `api.moonshot.cn` |
| OpenAI | [OpenAI](https://platform.openai.com/) | `api.openai.com` |
| Anthropic | [Claude Console](https://platform.claude.com/) | `api.anthropic.com` |

GLM／智谱本轮暂缓接入，不出现在供应商选项中。

每家供应商分别保留 Key 和已选模型。保存配置只影响后续请求，进行中的翻译继续使用原请求配置。完整刷新成功后若已选模型消失，扩展会保留原选择并要求重新选择，修复前不会发起新的远程翻译。升级时保留原 DeepSeek Key，但旧固定模型需要从新获取的 API 列表中选择。翻译目标仍是简体中文。

Key 保存在 `chrome.storage.local`，并限制为受信任的扩展上下文访问。这适合个人、本机、自备 Key 的使用方式，但 Chrome 本地存储并不是操作系统级密钥保险箱。

## 使用方法

1. 在普通 HTTP 或 HTTPS 页面中，用鼠标或触控板选中自然语言文本。
2. 点击选区末端旁边的圆形**译**按钮。
3. 如果主要语言被识别为中文，卡片会在本地原样显示选区；非中文或未知语言选区会发送到活动供应商，并以流式方式返回简体中文译文。
4. 结果完成后可复制；可重试允许重试的错误；也可通过 **×**、`Esc` 或点击卡片外页面关闭卡片。
5. 请求停止后，如果卡片遮挡正文，可拖动标题栏移动卡片。
6. 请求停止后，可拖动右下角手柄调整卡片宽高。关闭卡片或产生新选区前，当前卡片会保留该尺寸。

只有标题栏可以移动卡片，只有右下角手柄可以调整尺寸；关闭按钮、结果区和操作按钮保留原本交互。指针需要移动超过约 4px 才会真正开始任一手势，卡片会与视口四边保持约 8px 安全距离。首次有效移动后，卡片相对视口固定，页面滚动时不再跟随原选区。用户尺寸可以超过自动布局的 60vh 高度上限，超出内容只在结果区内滚动。尺寸和自由位置可跨重试保留，但关闭卡片或产生新选区后会重置。首次请求或重试仍在流式进行时，移动和调整尺寸都会被禁用。

## 当前支持

- 以本地解压方式安装的桌面端 Chrome Manifest V3 扩展。
- 顶层 HTTP/HTTPS 页面，包括本地开发服务器。
- 普通页面正文中的鼠标和触控板选区。
- 对完整选区只判断一种主要语言：使用 `chrome.i18n.detectLanguage`，并辅以 Unicode 兜底。
- 中文选区本地展示；非中文和未知语言选区使用选定的官方供应商流式翻译。
- 选区准入、5,000 字符上限、取消、过期结果隔离、超时、错误归一化、部分结果、重试、复制、深色模式和响应式卡片定位。
- 请求停止后的卡片拖动、视口边界限制、重试保位，以及锚定/自由位置两种滚动行为。
- 请求停止后的卡片尺寸调整、视口边界限制、重试保留尺寸、视口变化临时适配，以及结果区内部滚动。
- 固定的简体中文界面和简体中文翻译目标。

## 当前不支持

- Chrome 内部页面、Chrome 应用商店、`file://` 页面、内置 PDF 页面和 iframe。
- 键盘选区、键盘快捷键、右键菜单翻译和工具栏弹窗。
- `input`、`textarea` 或 `contenteditable` 内的选区。纯 URL、邮箱、数字、标点、空白和 Emoji 也不会显示触发按钮。
- 触摸屏、触控笔和多指手势的专项支持与验收。
- 目前仅实现上表中的官方平台；不支持自定义接口、订阅账号登录、手动模型 ID、自动供应商回退及同一家保存多套 Key。目标语言和界面语言仍不可配置。
- 模型出现在列表中不保证它支持扩展的翻译请求，可主动测试；能力信息不足的模型仍会保留为可选项。
- 翻译历史、缓存、云同步、账号系统、站点黑名单和扩展内暂停开关。
- 关闭卡片、产生新选区、刷新或导航后的卡片位置持久化。
- 卡片尺寸不会在关闭卡片、产生新选区、刷新或导航后持久化；同一卡片内也没有主动恢复自动尺寸的入口。
- 同时展示多张翻译卡片，或把混合语言选区拆成多段分别翻译；一次只处理一个完整选区和一种主要语言路由。

## 隐私与数据流

Highlight Translate 按以下流程处理每次选区：

1. Content Script 捕获完整选中文本，并在封闭的 Shadow DOM 中展示页面界面。
2. Service Worker 校验请求，并在本地检测选区的主要语言。
3. 中文选区直接返回，不请求供应商，也不依赖有效的供应商配置。
4. 对非中文或未知语言选区，Service Worker 使用本次请求已确定的供应商、Key 和模型，把完整选中文本连同扩展内翻译指令发送到该供应商固定的官方 HTTPS 接口。
5. Service Worker 把纯文本流式事件返回给卡片。模型输出始终按不可信文本处理，绝不会作为 HTML 执行。

扩展不会发送页面 URL、标题、DOM、HTML/CSS、附近文本、选区上下文或富文本样式，也不会保存选区、译文、历史或译文缓存。模型列表和供应商配置保存在本地。列表请求不携带选区，可选测试使用固定的非敏感文本。远程请求由所选供应商按照其自己的条款和隐私政策处理。

## 常见故障

### 没有出现“译”按钮

- 确认扩展已在 `chrome://extensions` 启用，然后点击**重新加载**并刷新网页。
- 确保当前是普通顶层 HTTP/HTTPS 页面，并使用鼠标或触控板完成选区。
- 确认选区不在可编辑区域内，并且至少包含一个自然语言字母。
- 纯 URL、邮箱、数字、符号、空白和 Emoji 会被主动忽略。

### 提示内容过长

把选区缩短到 5,000 个字符以内。过长选区仍会显示触发按钮，但会在本地被拒绝，不会发送给供应商。

### 提示需要 API Key

点击卡片中的**前往设置**，或点击工具栏图标，用对应供应商的 Key 获取列表、选择模型并保存，再重试。升级后即使已保留 DeepSeek Key，也需要获取列表并选择模型。中文选区在本地处理，不需要 Key。

### 连接测试或翻译失败

- 重新检查供应商、平台地区、Key 和已选模型，并确认 API 账号具有访问权限和足够的余额或额度。
- 检查网络、代理、防火墙和对应供应商的服务状态。
- 类似 `401`/`403` 的响应会显示为 Key 无效；限流、额度、服务端、超时、流格式和网络故障都会转换成简短中文提示，不暴露提供商原始响应。
- 自动化测试使用受控供应商响应；每家供应商的真实鉴权列表和翻译结果都需要单独验证。

### 卡片无法拖动

等待当前翻译或重试停止，再使用鼠标/触控板主指针拖动标题栏。流式期间会主动冻结拖动，结果区和操作按钮也不是拖动热区。

### 卡片无法调整尺寸

等待当前翻译或重试停止，再使用鼠标/触控板主指针拖动右下角手柄。流式期间会主动冻结尺寸调整。卡片会保持在视口内；视口过小时只临时约束实际显示尺寸，不会覆盖当前卡片已选择的目标尺寸。

### 重新构建后 Chrome 中没有变化

运行 `npm run build`，在 `chrome://extensions` 中重新加载 Highlight Translate，再刷新目标网页。本地文件变化后，Chrome 不会自动重新加载已解压扩展。

## 开发与验证

```bash
npm install
npm run dev
npm run typecheck
npm run lint
npm test
npm run build
npm run verify:dist
```

`npm run dev` 会监听源码并重新构建 `dist/`。`npm run build` 会生成可加载扩展，并自动检查 Manifest 入口、权限范围、五家固定官方主机、意外本地文件、疑似 API Key 和控制台日志。`npm run verify:dist` 可对已有构建重复执行分发检查。

修改界面后，还应在 Chrome 中重新加载 `dist/`，实际验证选区、翻译卡片、滚动、窗口缩放、复制、关闭、重试和拖动流程。自动化检查不能证明真实提供商请求或浏览器交互已经端到端成功。
